## What the public API supports

Use `email:read` to list owned Email Hosting services. Service records include their domain name, plan identifier, term, mailbox and domain limits, storage per mailbox, status, renewal dates, and auto-renewal state when available.

With `email:write`, you can request two operations for an owned service:

- Provision the service.
- Synchronize the service DNS.

Both operations require idempotency when called through the API. They are product workflows and can be accepted before downstream work completes.

```bash
curl --fail-with-body -X POST \
  "https://api.kmerhosting.com/v1/email/services/SERVICE_ID/dns/sync" \
  -H "Authorization: Bearer $KMERHOSTING_API_KEY" \
  -H "Idempotency-Key: email-dns-sync-20260831" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Mailbox administration and purchases remain console-managed workflows unless they appear in the public API reference.

## Set up an email domain

1. Choose an available Email Hosting plan and review live mailbox, domain, and storage limits.
2. Complete checkout with the domain you control.
3. Open the service's DNS page and copy every required record to the authoritative DNS provider, or use DNS synchronization when the portal confirms it can manage the zone.
4. Run verification and wait for DNS propagation before repeating the operation.
5. Create mailboxes within the plan limits. The address part before `@` may use letters, numbers, periods, underscores, and hyphens; use a temporary password of at least 10 characters.
6. Open webmail or configure an email client with the exact IMAP/SMTP hostnames, ports, encryption, and authentication shown by the portal.

## Mailboxes and aliases

The Email portal can create and delete mailboxes and rotate mailbox passwords. It validates the selected domain, address format, and minimum password length before sending a create request; a server-side failure remains visible in the form so it can be corrected or retried. Deleting a mailbox can remove access to stored mail; export needed data first. Alias controls can appear where the customer-facing product supports them—an alias routes mail and is not a separate mailbox with storage and login credentials.

## Renewals and suspension

The portal shows billing documents, transactions, renewal state, and applicable grace or suspension status. Keep enough account credit before the renewal attempt. If a service is suspended, resolve billing in the portal before changing DNS or recreating mailboxes; those actions do not renew the service.

<Warning>
Never send a mailbox password to support. If access is uncertain, rotate the password and update every mail client that uses it.
</Warning>
