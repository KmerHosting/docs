## Base URL and authentication

The production base URL is `https://api.kmerhosting.com`. Authenticate with an API key or, for the hosted MCP flow, a user-scoped OAuth access token.

```http
Authorization: Bearer kh_live_...
```

The interactive documentation is served by the API itself at [`api.kmerhosting.com/docs`](https://api.kmerhosting.com/docs). It always reflects the deployed gateway contract; use the reference pages in this site for KmerHosting workflows and security guidance.

The health endpoint is public: `GET /health`. All `/v1/*` operations require an appropriate scope.

## Response envelopes

Successful responses use this shape:

```json
{ "data": {}, "request_id": "UUID" }
```

Error responses use this shape:

```json
{ "error": { "code": "string", "message": "string", "request_id": "UUID" } }
```

## Writes and idempotency

Every documented mutation requires `Idempotency-Key`, 8–128 characters using letters, digits, `.`, `_`, `:`, or `-`. Generate it once per logical operation and reuse it only when retrying that exact operation.

```bash
curl --fail-with-body -X PUT \
  "https://api.kmerhosting.com/v1/domains/DOMAIN_ID/auto-renew" \
  -H "Authorization: Bearer $KMERHOSTING_API_KEY" \
  -H "Idempotency-Key: domain-renewal-20260831" \
  -H "Content-Type: application/json" \
  -d '{"enabled":true}'
```

Some writes return an accepted or queued result. Poll the relevant read endpoint or the customer console to observe product completion.

## Resource families

The exact endpoint definitions are generated in the [OpenAPI reference](/api-reference): account and API activity, service inventory, domains/DNS, Email Hosting, provider-neutral Shared Hosting, read-only LXC inventory, and KVM management. Use `GET /v1/account/api-usage` with `account:usage:read` to audit product and non-product calls, including operation IDs and source IPv4 values. The former `/v1/vps/*` resource is retired; use `/v1/lxc/*` or `/v1/kvm/*` explicitly.
